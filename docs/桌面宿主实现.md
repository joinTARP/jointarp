# 桌面宿主实现

桌面宿主固定使用 Electrobun 2.0.4、配套 Hutch 和 Bun 1.4.0，页面使用 React 与 Vite。开发机器的 Bun 只负责依赖与脚本，桌面运行时随应用提供。依赖统一在根级 Bun workspace 安装；`hutch.config.ts` 指定 Bun 与 Electrobun 版本，不维护额外锁文件。

## 页面与桌面通信

正式页面固定为 `views://main/index.html`。窗口创建时安装原生同步导航白名单，只放行该地址和哈希路由；不开放 `appdata://`，不载入远程页面。开发时，只有非发布构建允许访问本机 Vite 地址。原生桥确认页面外链使用 HTTP(S) 且不含嵌入凭据后，再交给系统浏览器打开。

`NativeMessagePort` 把 Electrobun JSON RPC 适配为 oRPC 的 MessagePort 接口：字符串直接传输，二进制帧转成 Base64。游戏路由、迭代器、取消与错误使用共享契约。页面完成原生桥握手后取得图片服务地址；刷新时主进程关闭旧连接并建立新连接，释放旧订阅，关闭窗口时也关闭端口。只有主窗口获得一次启动动画播放资格。

桌面设置、退出游戏房确认通过独立单向事件通知页面。页面只持有契约中声明的能力，不直接访问 Bun、Node.js 或文件系统 API。生产 CSP 禁止子 frame、任意内联脚本与远程脚本；仅允许同源静态计算 Worker，保留 SES 所需的动态编译，并只允许原生桥连接本机 WebSocket。文档公式在 renderer 本地 Worker 内执行，不经桌面 RPC 请求计算，隔离与恢复见[房间增量同步实现](房间增量同步实现.md#渲染端与生命周期)。

## 图片与单实例

本地图片服务仅监听 `127.0.0.1` 随机端口，请求路径包含每次启动生成的 256 位令牌。令牌只通过原生桥交给应用页面；每次读取图片仍须检查授权目录、真实路径、符号链接、扩展名，并确认目标为普通文件。响应禁用缓存与 MIME 猜测，不提供目录浏览或任意文件读取。退出时停止服务。

应用按配置目录建立单实例连接：Unix 使用权限为 `0600` 的本地 socket，Windows 使用命名管道。第二次启动唤醒原有窗口，CLI 预览同时传递绝对模组路径；异常退出后可恢复失效的 Unix socket。CLI 仍先校验预览目录，宿主再次校验后打开，不创建冒险。

## 数据库与打包

数据库直接使用内置 `bun:sqlite` 同步 API。`SqliteDatabase` 将参数数组和读取语句判定适配到 Kysely，提供同步事务、迁移与连接生命周期管理；随包使用 Bun 内置数据库驱动。

`electrobun prepare` 生成忽略提交的 `.hutch/devkit/`。Vite 单独构建页面，Electrobun 构建主进程；QuickJS Wasm 与运行依赖作为外部文件复制，其他业务依赖参与打包。源码显式注册动态迁移，数据库格式与业务契约由共享核心管理。

订阅认证通过 pi 的 `registerBunOAuthFlows()` 显式注册 OAuth 流程，使浏览器回调与设备码实现随主进程打包；默认的变量路径动态导入不能在打包后定位认证模块。订阅认证回归测试在独立临时目录运行实际 Bun 构建产物，用模拟认证响应验证浏览器地址、设备码与取消后的凭据状态。

开发模式运行 Vite HMR 与 Electrobun 主进程监听。发布模式生成平台安装器和 Zstandard 更新归档。发布验收解出归档，使用随包 Bun 验证 CLI、模组、数据库读写、事务回滚、重开恢复与 QuickJS Wasm；不从源码目录解析运行依赖。

## 平台边界

macOS 使用 WKWebView，Windows 使用 WebView2，Linux 使用 WebKitGTK 4.1；不捆绑 CEF。不同引擎的布局、中文输入、音频设备解锁和媒体播放需要分别验收。页面主题由应用配置和 ThemeProvider 管理。Windows 使用 `hiddenInset` 保留原生缩放边框，由 `WindowsTitleBar` 绘制随页面主题变化的标题栏；macOS 保留原生交通灯，Linux 保留系统窗口装饰。

Windows 不注册传统应用菜单，也不提供折叠菜单入口；设置保留侧栏入口，缩放与全屏等操作通过窗口内快捷键处理。窗口按钮和应用快捷键通过绑定当前窗口的原生桥执行，编辑快捷键由 WebView 处理；关闭动作调用 `requestClose()`，必须经过现有 `will-close` 离房确认，不能改成直接销毁窗口的 `close()`。窗口拖动、贴边、双击缩放、最大化恢复、全屏和中文输入需在 Windows 实机验收。

当前官方未发布 macOS x64 core，因此发布矩阵为 macOS ARM64、Windows x64、Linux x64。安装格式和签名流程见[发布流程](发布流程.md)。
