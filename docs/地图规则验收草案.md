# CoC 与 D&D 地图验收草案

状态：内部需求细化，尚待整体确认。上层范围见[地图功能设计讨论](地图功能设计讨论.md)。以下均为拟议验收场景，不表示功能已经实现，也不是规则教程。文中保留部分早期讨论过程；地图层级以“已确认的层级收敛与地图类型细化”为准，角色与物件以“环境物件：规则核对与已确认方案”为准，早期对应的待确认标记已被后续结论替代。

## 规则基线与职责

已确认用 CoC 第七版与 D&D 2024 基础规则作为首版验收基线。不能将 D&D 的固定战斗时长与移动预算套给 CoC，也不能将玩家一起提交行动视为角色同时执行战斗行动。

程序负责几何测量、预览与已裁定状态的展示，主持依据模组规则决定耗时、行动顺序、合法性、检定与中断。确认的结果决定位置与揭雾。移动预算是规则数据，不是所有模组必填的统一属性。

## CoC：调查与基础战斗

| ---- | -------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| C1   | 从城镇地图查看宅邸，再提交进入宅邸           | 查看不移动角色；主持确认后进入宅邸指定入口，未探索房间不暴露；返回父地图不等于离开宅邸                     |
| C2   | 调查员站在走廊，提交前往关闭的门并尝试开门   | 可停在门前；锁住或事件中断时不穿门，不揭示门后；门获准打开后按视野与墙体揭示                               |
| C3   | 点击书桌提交搜索，另一名调查员守门           | 可提交包含目标地点或物件的文字行动；主持结算搜索、守望和共同时间，不把搜索视为移动，不按点击次数计时       |
| C4   | 主持判定搜索需十分钟，第五分钟有人敲门       | 只推进到事件发生时，保留搜索未完成的事实；此处分钟数是测试剧情设定，不是 CoC 固定搜索规则                  |
| C5   | 两名调查员分在楼上与楼下                     | 独立位置与嵌套地图保持正确，全队共享地图信息；角色能否利用队友信息仍由主持判断，不把共享地图等同于角色感知 |
| C6   | 调查转入战斗，参与者按模组给出的敏捷顺序行动 | 地图展示当前行动者与顺序，可接受主持修正；不默认套用 D&D 的六秒一轮或固定格数移动额度                      |
| C7   | 调查员选择目标射击，或声明退到桌后           | 能测量距离、引用目标与掩体位置；射程、掩护效果与动作结果交主持，几何可见不等于必然能命中                   |

首版不自动执行 CoC 追逐流程；若发生逃跑，可交主持叙事裁定，但不得宣称已有追逐规则自动化。

## D&D：探索与战术移动

| 编号 | 具体操作或情境                                             | 拟议验收结果                                                                                             |
| ---- | ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| D1   | 配置每格五英尺，角色速度三十英尺，在无遮挡普通地面规划六格 | 显示路径距离三十英尺及预算；提交前不移动，主持确认后更新位置和本回合剩余额度                             |
| D2   | 同一角色先移动十英尺，攻击后再申请移动                     | 保留本回合已用移动量；不得因第二次提交恢复完整预算；是否允许后续移动由主持裁定                           |
| D3   | 路径含十英尺普通地形与十英尺困难地形                       | 主持结算后区分几何距离二十英尺与移动消耗三十英尺；地形由作者标注，地图只展示已知信息，不自动预览地形费用 |
| D4   | 本回合移动需求超出预算，玩家声明疾走                       | 提示需要额外行动支持，主持确认后更新预算与行动消耗；不能默认为玩家自动消耗动作                           |
| D5   | 角色斜走或试图斜穿墙角                                     | 按所选计距方式显示距离，不能斜穿阻挡墙角；替代斜向计距是模组选项，不混称默认规则                         |
| D6   | 角色规划路径离开敌人附近，途中可能触发反应                 | 主持可在途中停止，处理反应后继续或结束；不直接落到终点再补述结果，不从路径提示泄露隐藏敌人               |
| D7   | 大型生物占据多格，经过狭窄通道                             | 显示占地范围；主持能据此处理挤压、阻挡与通行例外，不仅按标记中心判断能否通过                             |
| D8   | 切入战斗后，多个玩家同时提交意图                           | 按主持确定的先攻顺序执行，后执行者依据先前结果重评；整轮时间不按参与人数重复累加                         |
| D9   | 玩家测量远程目标，或描述施法目标区域                       | 提供距离和目标引用；完整法术模板、范围命中与特殊感官自动化不作为首版通过条件，效果仍交主持裁定           |

已确认首版纳入困难地形标注、多格角色占地、同回合分段移动与途中暂停裁定；编辑器及交互需覆盖这些能力。

## 共同的可靠性验收

- AI 等待、失败或重试时，预览不得提交为真实位置；恢复后的移动不能重复扣时间或重复推进事件。
- 移动途中实际看见的范围可以成为探索记录；不能仅用终点视野遗漏沿途，也不能把尚未实际抵达的后半段揭开。
- 已探索但当前不可见的区域保留地形，不持续显示敌人实时位置；隐藏位置不能通过客户端数据或测距结果泄露。
- 多人客户端与重新载入后的角色位置、门状态、当前视野和探索记录一致。

## 本轮确认与下一轮待决

已确认规则基线、新增地图能力，以及全队共享视野的取舍。不同角色实际掌握的信息由主持裁定，首版不精确模拟各角色独立视觉与秘密情报。上述验收表仍是细化草案，未讨论的具体交互不能推定为已确认。

已确认的移动交互：

1. 移动结果按实际路径分段表达，每段包含实际位置变化及相关时间／资源变化；遇到需要玩家选择或反应时暂停，不能把尚未决定的后续路径当成已执行。
2. 已知区域允许规划路径与途经点；未知区域只提交探索方向或入口，不提供穿过未知区域的自动寻路与精确耗时预览。
3. 战斗中同一角色可以分次提交移动与动作，主持确认后更新剩余预算；需要玩家反应时保留当前行动上下文，不等到整轮所有动作都执行完才询问。

## 已确认的交互简化

地图以查看空间与表达移动意图为主，不提供开门、关门、解锁等专用按钮。相关行动通过正常行动描述交给主持，主持更新门状态，地图据此表现遮挡与通行。此决定不取消门的空间数据，也不取消已确认的作者编辑器。

## 已确认的空间编辑与裁定边界

- 作者可绘制困难地形区域并添加说明。地图展示已知区域，移动消耗由主持结算，首版不自动预览地形费用；此项替代此前地形消耗预览的建议。
- 作者配置角色标记占地大小，地图据此显示。狭窄通道能否通过、是否挤压由主持判断，不增加自动通行提示。
- 门由主持处理与更新；地图不提供开关门或解锁按钮。具体门状态分类尚未确认。

## 已确认的跨图连接约束

作者配置连接两端入口，默认双向，允许设为单向；主持决定是否通过。一次地图移动意图最多通过一个连接，到达后重新选路。尚未确认的移动不改变角色所在地图或揭示目标地图；无需玩家专用传送按钮。

拟议验收：配置地下室到下水道的连接，玩家提交穿过通道；受阻时停在原图，获准后到达目标入口，原路线终止。单向连接反向不可作为普通返回路线，分队仅移动实际通过的角色。已确认自己控制的角色跨图时自动跟随，队友跨图不强制切屏；上层仅展示角色所在地点，局部坐标变化不引起上层标记漂移。允许浏览队友所在地图与全队已探索地图，浏览不移动角色。

## 待确认：地图连接与层级

1. 父地图地点可以关联子地图，子地图允许多个具名入口；跨地图行动由主持选择实际抵达入口，不默认传送至中心。
2. 已确认：全局地图支持整张公开，或按作者划定区域由主持逐步揭示；场景地图使用角色视野揭雾。父地图揭示不自动揭示内部。
3. 初次制作地图时，作者设置父子关系、入口和比例尺；游戏中由主持更新角色所在地图与位置，浏览地图不改变角色位置。

## 地图层级的参考与待决建议

核对日期：2026-11-02。D&D 与 CoC 的不同尺度地图是冒险资料与使用方式，不应据此推导出强制父子地图数据规则。Chaosium 的 Arkham 官方资源同时提供州、城郊、城市地图及玩家／主持版本；D&D 官方资源同样提供区域与城市地图。

FVTT 以独立 Scene 为核心，每张场景有独立空间配置，通过目录组织及导航查看／激活；场景区域还支持跨场景传送。目录层级不等于角色必须依次穿越的空间层级。

据此建议：地图保持独立，以可选层级表达浏览归属，以入口／出口关联表达实际空间连接。玩家查看另一张地图与主持确认角色跨图移动保持分离。“每张子地图只有一个父级地点”仍是待决建议，不能将其当作 D&D、CoC 或 FVTT 的既定要求。

## 当前讨论焦点：地图归属

用户要求继续讨论每张地图是否有唯一上级。暂不确立单父级树结构。需区分浏览返回路径、地图在世界中的位置归属、实际入口出口连接；以跨多个建筑的下水道和移动中的船舱检验模型，避免强行给独立地图指定错误的固定地理归属。

## 收敛建议

用户提出避免过度设计。下水道多个入口已由跨图连接覆盖，不构成多上级模型的必要理由。首版建议仅保留地图可选单一上级与已确认的跨图连接；不为不同尺度重复引用、移动船舱等尚未请求的情境增加模型。此前这些例子只作讨论，不作为验收要求。此收敛建议待确认。

## 已确认的层级收敛与地图类型细化

用户已同意可选单一上级用于嵌套浏览，跨图连接独立表达通路。多上级引用与独立归属模型不进入首版。用户进一步提出：概览地图只允许前往固定地图点，不能自由移动坐标；场景地图允许坐标目标与路径。

拟议验收：城镇概览上存在酒馆与教堂，玩家只能选择这些地点提交移动意图，不能把角色拖到空白处作为目的地；场景地图允许指定具体空间位置。选择目的地仍不直接生效，主持统一裁定耗时与事件。已确认概览地点不强制连线，主持裁定可达性、路线与耗时；已确认抵达不自动进入场景，是否进入及实际入口由主持裁定。

已确认：概览地点关联场景时，抵达后是否进入及实际入口由主持裁定；只到门口与进入室内可以是不同结果。没有场景地图的地点可直接进行文字行动，不要求创建空场景。

已确认：概览旅行途中被事件打断时，显示“前往某地途中”，不虚构概览坐标或提前标记抵达；事件有场景图则由主持切入，没有则用文字继续。该决定仅定义位置表现，不引入旅行进度条或自动计时系统。

已确认：主持可直接修正角色所在地图与位置、门状态和揭示范围，用于传送、剧情变化或纠正裁定；地图几何不能成为阻止这些合法修正的硬规则。已探索但当前不可见的区域保留地形，不显示 NPC／敌人及其移动，也不显示最后位置残影。具体工具契约需在调查现有文档更新与权限机制后设计。

下一轮待确认：地图保存恢复需保留角色位置、门状态和探索记录；首版以地图关联现有角色资料来放置角色及 NPC 标记，不新增独立角色编辑系统。技术契约与权限设计须结合仓库现状调查，不能仅凭访谈默认实现。

## 环境物件：规则核对与已确认方案

已确认角色与 NPC 标记关联现有资料，复用名称与头像，不新增角色编辑器。

规则核对：D&D 2024 包含物件交互、物件损坏与掩护；CoC 基础战斗包含寻找掩护的反应。因此不提供玩家专用物件按钮不妨碍主持裁定，但把全部物件永久烘焙到底图会限制搬动或破坏后的准确展示，不能声称完整覆盖动态环境。

已确认：装饰画入底图；对位置或状态变化有意义的物件，可用简单标记与已有资料或文字说明表达，由主持调整位置、状态或移除；不增加专用玩家操作菜单、自动物理或自动掩护计算。墙体视野遮挡与规则上的掩护不能直接等同。

来源：[D&D 2024 游戏规则](https://www.dndbeyond.com/sources/dnd/br-2024/playing-the-game)、[D&D 规则术语](https://www.dndbeyond.com/sources/dnd/br-2024/rules-glossary)、[CoC 战斗规则](https://callofcthulhuwiki.chaosium.com/rules/combat.html)。

## 已确认的视野验收边界

同一场景按队伍角色视距与墙、门计算各自视野并取并集；跨图不混合坐标。首版不自动模拟复杂光源或黑暗视觉，主持可调整视距或揭示范围。物件标记默认不遮挡视野，作者或主持可明确设置遮挡；掩护数值与完全阻断视线分别裁定。

拟议验收：两名角色分别观察走廊两端时共享可见范围；关门后不能看见门后的实时敌人，历史地形仍保留。普通箱子标记不会无意产生黑墙，明确设置的遮挡才影响视野。

## 已确认的房间界面验收

地图面板位于世界状态下面，世界状态可折叠，地图保留稳定的可用高度，可以收起或展开大图；两种视图共用地图状态。支持缩放、平移、回到自己角色、切换已知地图和已确认的移动意图操作；概览图不能选择任意坐标。视图变化不触发角色移动，不另建导航小地图。

已确认布局收敛：首版不增加拖拽停靠、自定义位置或独立地图侧栏；具体尺寸以实际布局验证为准。
