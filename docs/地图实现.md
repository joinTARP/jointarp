# 地图实现

当前实现覆盖手写场景地图、墙门遮挡与探索记录、主持地图工具、行动移动意图及房间地图面板。概览地图、父子地图与连接、作者编辑器仍属于后续阶段，不能由设计讨论推定为已实现。

## 模组加载与坐标

`packages/module/src/schema/map.ts` 定义地图结构，`node/module-maps.ts` 扫描 `maps/` 中的 JSON/TOML；地图标识是去掉目录前缀和格式扩展名的相对路径。同名两种格式报冲突，地图不是游戏文档类型。完整校验同时检查底图与文档引用；创建冒险时地图配置随基础模组编译成 JSON。

底图、墙、门、区域、起点与初始标记使用像素坐标，原点在左上角，y 向下。`schema/map-geometry.ts` 统一距离换算、路径测量、遮挡、视野和探索位图；支持方格与无网格。主持工具的坐标和距离换算成地图距离单位，不能直接混用像素。命名区域提供空间语义，不决定规则效果；凹形区域的默认锚点必须位于多边形内部。

## 权威状态与投影

`packages/core/src/node/sessions/map-state.ts` 保存房间地图事实，文件与恢复职责见[存档格式](游戏房间存档格式.md#地图状态)。地图位置、门状态和探索记录由平台维护；模组自定义位置与时间字段仍由主持维护，两者互不同步。

`map-space.ts` 按同图队伍角色的视野取并集，墙、关闭的门及显式遮挡标记影响可见范围。探索记录累计保留地形；视野外的非队伍标记不显示，也不保存最后位置残影。`map-projection.ts` 只投影已知地图；隐藏标记不显示，未揭示秘门以无标识墙段出现。静态资源不包含初始标记、区域与起点，但包含底图和墙线，不能把视觉迷雾当成原始素材的传输权限隔离。

## 主持裁定与行动意图

`agent/map-tools.ts` 提供 `map_read`、`map_move` 和 `map_update`，通过 `sessions/map-commands.ts` 执行。读取包含幕后区域和隐藏标记，主持必须按角色实际感知叙述。移动可引用玩家消息意图，或以起点、区域方位、标记旁侧和距离单位坐标指定目标；目标寻路绕开墙与关闭的门，沿意图执行时遇阻停止。`until` 限制本次距离，工具返回实际移动、剩余距离、阻挡与新见标记；规则裁定先于移动，到达叙述以成功返回为准。

`map_update` 处理放置、跨图修正、移除、标记属性、门及秘门揭示和地图已知状态。普通移动服从空间阻挡，直接放置用于主持合法修正；物件阻挡通行是提示，不替代主持裁定。地图不自动结算检定、移动预算、地形费用或行动耗时。

`map-intent.ts` 在主机接收行动时验证地图、本人控制权、范围与墙线，并记录当前位置为起点。每条行动最多附一张意图卡，可不附文字；聊天不能附卡。关闭的已知门允许规划经过，由主持裁定。终点未探索时记录探索方向，预估距离为 `null`。提交、接收及保存意图均不直接移动标记；主持执行后另存意图进度。

`map-description.ts` 把路线、区域、门、重叠、窄道与未探索区域转换为主持语义上下文。幕后路线描述不直接放进玩家意图卡；距离与风险提醒不等于规则裁定。

## 房间界面

`apps/desktop/src/renderer/src/features/maps/` 通过 `map-model.ts` 消费地图资源与房间投影。`MapPanel` 位于世界状态下方，`MapDialog` 提供大图浏览、平移缩放与本人角色的路点规划，两者共用投影和 `map-ui.ts` 的本地草稿。视角按房间和地图保存在 `map-ui.ts` 的内存状态中，以地图中心坐标和缩放值记录，关闭大图、切图及调整窗口后保留观察中心；重启应用不保留。视角工具提供本人定位、全图适配与缩放。规划预览复用 `summarizePlan` 与已知墙线，点击时仍独立校验；添加到行动后由弹窗关闭焦点回到输入框，随行动发送，不直接修改权威位置。

`MapTerrain` 与 `map-fog.ts` 为小图、大图统一绘制三层地形：未知区域保持实色遮罩，已探索区域以低饱和、低亮度底图保留地形记忆，当前视野显示原色。历史探索格按连续行段直接绘制到地形画布，不再平滑放大低分辨率探索遮罩；探索位图的格心判定与存档精度不变，墙边仍可能存在一个探索格量级的近似误差。当前视野继续使用主机下发的多边形，不对墙边做模糊。

视野变化只对已确认地形做 180 毫秒淡入：旧画面先与新视野相交，失去视野的区域立即退回地形记忆，清空探索时立即遮黑。动态标记继续直接消费最新投影，不保留旧标记参与淡入。快速连续更新会取消上一段动画，从当前画面重新过渡；首次载入、切图与系统偏好减少动态效果时直接显示目标画面。本轮不插值角色位置或推算沿途视野，也不引入光照或个人迷雾。

`ChatComposer` 将草稿随行动提交，`MovementCard` 展示路线摘要；待裁定路线以虚线呈现，同一标记只显示最近且仍从当前位置出发的意图。实际位置以房间状态为准，本地草稿不承担存档恢复职责。

## 验证边界

共享几何、模组加载、地图状态、主持命令及行动接入的测试使用独立平台数据。改动空间状态、消息或同步链路后执行根级全量测试、类型检查和桌面构建。CLI 校验只能证明配置与资源符合约束；真实模型需通过 MCP 临时局验证初始化、工具调用、遮挡、分段移动及叙述保密。当前 MCP 的步骤快照只保存文档，地图变更还需对照临时局 `map-state.json` 与真实模型工具记录；不能把文档快照当作地图状态快照。缩放、点选、明暗主题和底图对齐仍需实际界面验收。
