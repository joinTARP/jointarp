# 模组加载与文档实现

本文说明共享模组核心、配置存储、计算与展示的实现及开发约束。面向模组作者的文件格式、字段参数和完整示例统一维护在官网：「模组结构」、「文档类型」、「计算字段」、「展示布局」。

## 共享核心与加载链路

`packages/module/` 提供桌面和 CLI 共用的 Schema、字段计算、引用、开局和模组校验，不能依赖 Electrobun、React、桌面源代码或个人应用配置。`packages/module/src/schema/` 可用于主进程与浏览器，`packages/module/src/node/` 负责文件加载和编解码；固定功能测试模组在 `packages/module/test-fixtures/platform/`，临时副本工具与测试类型在 `packages/module/src/testing/`。

- `node/config-file.ts`：JSON/TOML 配置发现与解析；同名的两种格式同时存在时报冲突，不设格式优先级。
- `node/document-types.ts`：字段定义和布局加载，遇到未知配置项或不合法引用时，报告具体路径。
- `node/document-codec.ts`：三种文档格式统一到结构化模型。Markdown frontmatter 是属性，正文归一化到 `body`；序列化时重新分离。
- `node/module-documents.ts`、`node/validate-module.ts`：文档扫描与完整模组校验。游戏文档的类型由一级目录决定，子目录可继续嵌套分组；文件名不重复类型。扫描跳过隐藏目录、`node_modules` 和 `AGENTS.md`，文档身份包含类型目录与完整分组路径，不含内容扩展名，重复身份报错。根目录文档须声明为阅读页，未知类型目录中的游戏文档报错。
- `schema/document-path.ts`：统一解析一级类型目录、文档标识与保存格式，供加载、运行时读取、新建、搜索及房间投影复用。
- `schema/document-evaluator.ts`：按文档读取和计算；客户端 Worker、主进程与 CLI 共用，客户端按批次注入 SES 编译器。
- `schema/document-computations.ts`：文档顶层 `computed` 校验与有效字段定义，覆盖只作用于当前文档。
- `schema/document-type-rules.ts`：基础类型与单文档有效定义共用的实例原始状态约束校验。
- `schema/document-references.ts`：原始字段声明引用的收集、直接引用图与反向失效遍历；不执行公式。带格式扩展名的引用归一化到同一文档身份，声明与 `load()` 参数可采用不同写法。

`validateModule` 分别检查原始文档声明和计算结果中的引用，避免公式覆盖掩盖无效原值；相同无效目标不重复报告。初始化检查复用原始文件内容，创建房间时所有文档的原始引用均需符合目标存在与类型约束。

TOML 编解码不能引入与 JSON 不同的日期对象、非有限数或危险键。TOML 作者文件不表达 `null`，删除字段由业务更新操作表达。创建冒险时 `core/node/sessions/compile-module.ts` 将复制后的配置及游戏文档编译为 JSON，保留原值和公式，不保留 TOML 注释、排版或 Markdown frontmatter 外壳；阅读页与附件保留。运行时路径由 `game-document-path.ts` 统一解析：省略或填写三种格式扩展名均定位同一文档，内部存储和缓存使用唯一实际路径。创建与覆盖契约见[游戏房间存档格式](游戏房间存档格式.md)。

## 导入边界

桌面入口 `modules.importLocal` 根据 `kind` 打开 ZIP 文件或文件夹选择器，取消时返回 `null`；本机路径由主进程选择，不经渲染进程传入。`modules.importGit` 只接受仓库地址，导入默认分支最新内容，模组固定放在仓库的 `module/`。界面入口为 `ImportModuleButton.tsx`。

`apps/desktop/src/main/modules/module-import.ts` 统一协调目标目录锁、隐藏临时目录、元配置与文档类型校验、发布和失败清理。本地文件夹与 ZIP 目标目录同名时拒绝覆盖；Git 来源按 origin 识别，GitHub 的 HTTPS 与 SSH 地址统一为 owner/repo，不同作者的同名仓库分别保存，无关目录不覆盖。同源重导先由全局任务服务确认丢弃本地修改，再下载校验并在目标锁内替换；切换失败恢复原目录，恢复失败保留隐藏备份路径并报错。校验使用 Zod 与共享模组加载器，文档内容问题在打开模组、创建冒险或执行 CLI 校验时处理。文件夹导入允许选择内容目录或包含固定 `module/` 的仓库外层，只复制内容，不修改源目录。Git 导入整体保留浅克隆仓库、远程地址和分支跟踪关系；发布目录是完整仓库，校验和返回路径指向其中的 `module/`，目录名不追加子目录后缀。

`module-root.ts` 统一解析直接内容目录与固定 `module/` 外层：双层清单报结构冲突，缺少清单报明确错误，内部 `module/` 符号链接被拒绝；模组库条目的根路径仍允许本地快捷方式。列表只展示一个模组，`ModuleSummary.path` 指向实际内容目录，预览、阅读页、媒体授权和新建冒险使用该路径，不扫描仓库说明与 Git 元数据。

模组列表只解析内容目录和读取元配置，为卡片提供名称、描述、封面等信息，不加载类型定义、布局、阅读页或游戏文档，不遍历内容目录、不统计文档数量、不执行公式，也不调用完整 `validateModule`。卡片只展示目录或元配置读取错误；类型、文档与公式结果中的问题在显式打开模组、创建冒险或执行 CLI 校验时处理，创建冒险按钮不依赖列表预校验。

应用不自动拉取或监听文件。列表与预览路由通过 staleTime=0 的 fetchQuery 在重新进入时读取文件，不复用一分钟内的旧结果；组件沿用已加载的查询数据。用户手动更新仓库后，下次列表请求或重新打开预览读取新内容；已有冒险使用独立模组副本，只有显式同步才替换；新冒险使用更新内容。Git 导入只跟踪默认分支；文件夹与 ZIP 导入仅保存内容副本。

官网一键导入使用 `tarp://import?repository=owner%2Frepo&revision=<SHA>`，revision 可省略，仅用于与下载后的 HEAD 比较并显示提醒，不影响默认分支下载。链接入口只接受 GitHub 仓库标识；未知参数、重复参数、其他协议及本机路径拒绝。官网目录同步也读取默认分支 HEAD。

`ModuleImportService` 统一管理 Git、ZIP 和文件夹的忙碌状态、替换确认与结果。任务保留在主进程，渲染层通过 RPC 读取状态；一次仅接受一个任务，忙碌时提示重试，不排队。对局中成功只提供打开入口，其他主窗口页面成功后打开模组。资料参考窗口不消费导入结果。

本地来源选择期间使用 `selecting` 状态并保留任务互斥，选定路径后才进入 `running` 并读取保存目录、执行导入；取消选择回到 `idle`，不执行导入。导入按钮轮询主进程状态以区分选择和导入阶段，全局进度提示不展示 `selecting`。

启动参数在 CLI 解析前分流导入链接；原生 open-url 与第二实例激活消息进入同一服务。现有 Unix socket / Windows named pipe 转发带类型的唤醒、预览或导入请求；初始化期间缓存导入请求，窗口就绪后处理。macOS 正式包声明 URL scheme；Windows 正式版 GUI 启动时向当前用户注册 launcher 协议命令，不要求管理员权限。开发构建不抢占正式协议。Windows 卸载可能残留注册，升级或重装后首次启动重新写入；Linux 不注册协议，使用官网复制地址和手动 Git 导入。

`packages/module/src/node/extract-zip.ts` 在新建临时目录逐文件流式解压，拒绝越界路径、符号链接、特殊文件、加密条目和重复路径。路径检查兼顾 Windows 名称限制与大小写、Unicode 别名；忽略 `.git` 与 macOS 归档辅助文件，保留 `.types`。ZIP 文件与单文件各限 512 MiB，解压总量限 2 GiB，条目限 10,000 个。归档根目录含配置时直接使用，否则查找唯一模组根目录；存在多个候选时拒绝自动选择。

玩家操作说明统一维护在官网「第一次冒险」。

## 已有冒险的模组同步

核心 `sessions/module-sync.ts` 保存本机来源、构建编译候选并比较内容指纹；桌面 `sessions.module` 提供来源选择、手动检查和同步入口。来源目录单独保存在房间的 `module-source.json`，不进入公共房间资料或玩家同步；没有来源记录时由主进程目录选择器绑定。检查只由按钮触发，不监听文件、不检查窗口焦点、不拉取 Git。指纹覆盖编译后的配置、文档、阅读页和附件，包含路径与实际内容，不依赖模组版本号或文件时间。

同步由 `ChatService.syncModule` 协调：AI、开场、序章播放、回应队列及房间配置操作未结束时拒绝；进入维护状态后关闭旧运行连接及 AI 资源，拒绝新提交。核心持有 `game/` 锁，将来源编译副本与当前覆盖合并，先检查原值、引用、公式、权限、角色及开局进度和同步容量，再发布新副本。未覆盖字段继承新值，已有覆盖、数组整体覆盖和本局新增文档保留；新角色建立索引，已有角色 ID、归属、退场标记和队友席位保留。如果同步会删除有覆盖或角色记录的基础文档、与本局新增文档冲突、改变正在建卡的工作台，或造成其他不兼容变更，则拒绝同步，不重新初始化开局。发布与恢复边界见[房间存档格式](游戏房间存档格式.md)。

发布后更新全部已打开数据库连接的类型与基础文档，清理文档计算和房间投影，推进原、新文档版本。桌面发送窗口刷新自身，其他窗口通过统一广播重新加载本地资源和同步基线；图片地址增加本机刷新版本，避免同路径附件沿用旧缓存。聊天和 Pi 历史保留，下一轮 AI 重新读取新模组；本局主持指令和其他独立设置不随模组替换。结束的冒险需先重新开启才能同步。

## 应用配置与房间设置

应用级配置由 `apps/desktop/src/main/config/app-settings.ts` 统一校验和保存，默认文件 `~/.tarp/settings.json`，`TARP_HOME` 可覆盖配置根目录。文件只支持标准 JSON，不支持注释、尾逗号或 TOML，分为 `app`（主题、模组目录）、`game`（玩家身份与 `defaults` 游戏默认配置）和 `tts`（语音供应商连接与凭据）三个分组。`app-config.ts` 与共享 `appConfigSchema` 只处理公开的 `app` 分组。默认模组库位置取系统文档目录下的 `tarp/modules`，应使用系统路径接口处理 Windows / OneDrive。

只有文件不存在时采用默认值。已有 JSON 解析失败（包括空文件）或 Zod 校验失败时，报告文件路径和字段问题，保留原文件并禁止保存；启动读取失败会提示并退出。错误提示不回显配置原文。业务补丁保存必须先成功读取，不能用默认值覆盖坏文件。

冒险级设置由 `packages/core/src/node/sessions/room-settings.ts` 独立校验和保存，文件为冒险目录内的 `settings.json`，只支持标准 JSON。分为 `chat`（提交与插话）、`display`（展示）、`ai`（主持模型）、`hostSystemPrompt`（主持指令正文）、`compaction`（压缩阈值）、`tts`（语音开关、自动朗读、无凭据的供应商与声音配置及主持覆盖）、`companion`（新增队友模板）、`companionRoleplayPrompt`（队友扮演指导正文）和 `contextSubscriptionsEnabled`（上下文订阅开关）。文件必须存在；缺失、符号链接、JSON 或字段错误均拒绝读写，保留原文件。

前后端通过 `roomConfiguration` 提取房间的公共配置，剥离提交方式版本与主持声音覆盖。房间字段补丁复用 `patchGameDefaults` 的合并结果，再保留房间专有字段；主持指令恢复默认时解析为正文，提交方式版本由设置写入入口按实际变化推进。

模型选择只保存服务商 ID、模型 ID 和展示信息，不保存 API Key。模型选择、声音覆盖和压缩阈值可显式保存 `null`，分别表示未选模型或继承、继承默认声音和自动阈值。队友专属的模型、主动性、文档查阅开关与声音随 `adventure.json.party.companions` 中的队友实体保存，不写入房间设置；新增队友从本局 `companion` 模板复制模型策略、主动性、文档查阅开关与默认声音；模板之后的修改不改变已有队友。声音模板写入席位 `defaultVoice`，不混入优先于模组的个人 `voice` 覆盖。具体优先级由功能入口解析。

冒险状态独立保存在 `adventure.json` 的 `room`、`notes`、`launch`、`party` 和 `contextSubscriptions`，由 `room-storage.ts` 校验和保存；字段职责见[存档格式](游戏房间存档格式.md)。两份文件各自同步读改写及原子替换，不互相覆盖或隐式初始化。开局与队伍事务只暂存自身状态，提交时保留资料和笔记的最新内容。锁、错误与跨进程边界见[文件存储](文件存储.md)。

应用的三个分组共用按路径串行的异步读改写队列，保存时只替换所属分组，并保留其他分组；玩家身份在 `game` 缺失时原子初始化，语音缺省读取与临时试听不创建文件。默认配置统一通过共享 `game-defaults.ts` 校验；补丁仅合并明确提交的字段，包括语音配置与队友互动的内部字段，避免旧窗口整页值覆盖并发修改。创建 session 时一次性复制默认值，主持指令为 `null` 时解析内置正文后保存；运行时不读取应用默认配置。未连接的模型与语音供应商引用仍保留，不阻止创建，也不自动切换服务。应用配置仅使用现行文件结构，开发版本兼容策略见[存档格式](游戏房间存档格式.md)。

AI 模型与协议由 pi 的 `ModelRuntime` 管理，自定义服务商定义保存到 `models.json`，AI API Key 和订阅凭据由 pi 保存到 `auth.json`；每个服务商只有一套连接，以服务商 ID 和模型 ID 选择模型。内置模型目录由 pi 提供，不复制进配置；动态模型缓存使用内存，不额外创建缓存配置文件。应用保存 `models.json` 时使用标准 JSON，保留其他服务商和已有模型的高级参数，之后由 pi 重新加载。语音凭据继续保存在 `settings.json` 的 `tts` 分组。所有凭据均不能经普通配置接口返回，也不能混入房间文档或公开投影，见[聊天与 AI 实现](游戏聊天与AI实现.md)和[语音朗读实现](语音朗读实现.md)。

## 文档更新与正文权限

`packages/core/src/node/sessions/game-state.ts` 在房间锁中重新读取合并文档；主持 `update` 与 `batch_update` 共用 `game-document-patch.ts`，使用 `fast-json-patch` 执行受限 RFC 6902（`add`、`replace`、`remove`、`test`），由 `game-pointers.ts` 检查 Schema 权限。操作在独立原始候选上按顺序执行；`test` 可检查只读字段的原始值，不写入计算结果，修改仍须经过可写权限检查。数组插入与删除须具有列表容器的写权限，不能借可写子字段改变只读列表结构。

`batch_update` 只更新已有文档，同一批不能重复指定同一文档；所有候选先共同校验内容、引用、计算结果和累计同步容量，引用计算采用同批目标的最终候选值。整批通过后暂存全部文档和一份合并引用索引，再按请求顺序发布。`update` 使用同一提交入口处理单文档。校验、暂存和发布前取消均不发布文档；开始发布后不因取消主动中断，文件系统失败仍可能部分成功，错误明确列出已保存和未保存路径。文件、索引和关联房间 JSON 不构成跨文件事务，恢复边界见[房间存档](游戏房间存档格式.md#写入与恢复边界)。`write` 仅创建新文档，不能覆盖基础文档或修改类型和附件。

内置 `name`、`description`、`image`、`avatar`、`body` 与普通字段共用权限和计算规则。字段默认只读，显式 `mutable: true` 才允许运行时修改；计算字段不能同时可修改。**Markdown 正文没有额外只读限制**：声明 `fields.body.mutable = true` 后，`update /body` 可写入正文覆盖；没有声明则拒绝。作者的 Markdown 原文件保持不变；创建房间时，游戏文档副本编译为 JSON，正文保存在 `body`。本局修改写入 `game/` 中对应的 JSON 覆盖文件，读取时与基础副本合并，正文按 Markdown 渲染，不重建 Markdown 文件。覆盖继承与只读权限的回归位于 `game-overlay.test.ts` 和 `game-state.test.ts`。

AI `read` 返回计算后的 JSON 视图，与原值不同的字段保留 `_字段名` 原值；`update` 使用原字段路径。字段 `visibility` 控制玩家投影，不能等同远端权限或过滤完整原始同步，见[增量同步](房间增量同步实现.md)。

## 计算与展示契约

### 公式配置与有效定义

文档顶层 `computed` 保存字段路径到表达式的映射，优先覆盖类型默认 `compute`；没有文档覆盖时沿用类型默认公式，没有任何公式时保留普通原值。共享 `resolveDocumentComputations` 在原值校验、根与引用目标求值、名称定位、草稿校验中生成单文档有效字段定义，不修改共享类型。点分隔路径支持对象和对象列表子字段，列表路径适用于全部条目，不支持按下标为单个条目声明公式。

文件边界保留顶层 `computed` 的公开格式；内部 `DocumentData` 将业务原值 `values` 与公式配置 `computed` 分开，`ParsedModuleDocument`、计算输入和角色草稿采用相同结构。原始加载及同步使用 `RawModuleDocument` 携带独立配置，计算展示使用 `ModuleDocument`。文件读取时拆分配置，源数据校验与落盘时通过 `documentSourceValues` 合回文件结构；求值只读取独立的业务值，嵌套同名业务字段属于普通数据。

有效定义按基础类型对象和排序后的公式配置内容缓存，业务值变化、重复解码和配置键顺序变化不会重新构建。每个类型最多保留 128 种配置组合，超过时淘汰最早缓存项；类型对象通过 `WeakMap` 管理，遵循只读契约，重新加载类型使用新的对象和缓存。公式内容改变会生成新定义，校验失败不缓存。基础类型和覆盖后的定义统一调用 `validateDocumentTypeRules`，避免实例约束在两处重复维护。

目标必须是已声明的只读字段；覆盖可使该字段的原值省略，即使类型的普通字段声明了 `required`。结果继续按原类型、枚举、引用和布局约束校验，可见性不能由文档公式改变。实例原始状态约束仍检查有效定义。未知路径、空路径段、保留键、空公式、超过 2048 字符的公式，以及覆盖可写字段均拒绝。顶层 `computed` 不能声明为业务字段，嵌套业务对象中的同名字段仍是普通数据。配置区不进入 `$raw`、`$self` 或计算展示结果，完整配置由作者通过文件系统使用编辑器检查。

文档公式以独立配置参与房间累计覆盖与渲染进程计算输入，协议版本保持 `1`；本局新建文档可携带公式，已有文档的 `update` 不能修改 `computed` 配置。模组公式从房间冻结副本继承，普通值变化仅保存本局差异；派生结果不写回文档。引用目标始终使用目标自己的覆盖公式，读取权限继续限于原值中声明的引用。声明引用索引指纹包含 `computed`，公式配置变化或恢复原始版本会使相应计算结果失效。

### 求值、引用与错误传播

根字段、对象及列表子字段在同一次求值中按实际读取执行；Node 默认的原生 `Function` 编译器按表达式缓存，最多保留 256 项；客户端使用按批次新建 Compartment 的 SES 编译器；`$self`、`$item`、引用值只读。计算字段 getter 在缓存结果前调用共享 Schema 校验，不复制第二套类型规则。公式报错、循环依赖、`undefined` 或类型错误使对应字段失效；实际读取失败字段的计算字段同样失效，即使公式捕获异常并返回默认值，该依赖失败仍会使字段失效。字段的失败状态及实际求值依赖仅在本次求值中保留，值通道输出 `null`，错误通道使用本次投影的 `fieldErrors`，按完整字段路径记录原因，名称失败由文档投影显示“未公开资料”，不回退原名。

客户端公式在专属 Web Worker 内使用 SES，输入及辅助函数冻结，宿主 API、系统时钟与随机源不注入；lockdown 只冻结 Worker realm，不影响 UI。Node 权威读取、提交校验及 CLI 仍按可信模组原生执行。两端共用完整调度与校验，不提供独立堆或累计输入限额。整体求值失败时保留普通原值，全部计算字段失效并记录对应错误。

`load()` 返回目标的冻结计算视图，属性读取时才执行所需公式，目标公式可以继续读取自己的声明引用。每个 getter 使用所属文档的独立 `$raw`、`$self`、`$item` 上下文，本次入口内按输入对象和字段单元缓存；双向文档引用合法，实际字段求值循环才失败。引用解析只取同一快照中由原值和目标类型声明的引用，不开放任意路径，也不应用目标的整份显示过滤。派生值不写入存档。缓存、计算器生命周期和非确定性公式的限制见[增量同步](房间增量同步实现.md)。

计算字段允许保存同名原值，存在时按声明类型校验，仍不能配置 `required` 或 `mutable`。所有公式通过 `$raw` 读取冻结的原始文档根，通过 `$self`、`$item` 读取计算视图；计算器返回独立结果，不修改输入。名称须返回非空文本，其他计算字段可返回合法空结果 `null`；合法空值的展示由 `hideWhenEmpty` 控制，不参与计算依赖；错误先显示“计算失败”，不受空值隐藏配置影响。`undefined` 和错误类型属于计算错误，失效结果输出 `null`，严格校验时拒绝。公式结果在 JSON 序列化转为 `null` 前检查非有限数，`NaN`、`Infinity` 和 `-Infinity`（含对象、列表中的值）属于计算错误，失效结果输出 `null`，严格校验与状态提交拒绝；主动返回 `null` 仍为合法空结果。名称不接受 `null`，原始数字也须为有限值。

字段类型校验区分原值与计算结果，递归覆盖对象和对象列表：原值不接受声明类型之外的 `null`，计算结果仅对声明了 `compute` 的字段允许 `null`。直接复用或展开计算视图可以保留合法 `null` 子字段；实际读取失败子字段时，整个派生字段失效。Markdown 正文与其他格式一样可以保存原始 `body` 并同时配置公式。

### 读取视图与严格校验

模组库入口调用 `loadModuleLibraryDocuments`，一次扫描返回布局展示文档，不额外复制或传输原始文档。`library` 视图优先保留原始字段，缺省的派生字段补充计算结果；对象和数组保留原始结构，不混合重排后的计算结果。计算字段失败不影响原始资料浏览。加载器默认 `source` 视图用于模组校验和创建冒险，保留文件元数据并严格检查计算业务字段；`raw: true` 跳过计算；游戏的 `public` 视图始终使用计算结果，失败字段输出 `null`，不回退原值。两种错误处理策略共用同一计算器，严格模式仅在求值完成后拒绝实际计算错误；主动返回 `null` 的空结果不算错误。状态提交显式启用严格计算校验，在任何文件与版本发布前拒绝公式错误，提交仍须校验原始类型、引用和写权限。

`DocumentLibraryScope` 仅标记模组库展示范围，允许布局展示主持字段和隐藏资料，不持有原始文档数据。文档详情统一使用展示布局；查看完整原始文件由用户通过文件系统使用任意编辑器完成。

### 可见性与空值展示

文档类型可配置 `displayWhen`，表达式与字段计算共享求值上下文、Schema 和失效传播，但内部条件单元不进入 `$self`、原值或 `values`。条件只接受布尔值：`true` 显示，`false` 合法隐藏；`null`、`undefined`、报错和错误类型展示时隐藏，严格提交时拒绝。显示条件可以正常读取合法 `null`，字段的空值隐藏配置不影响条件求值。没有条件默认显示。条件即使为 false，也不免除根文档的全部业务计算校验；引用目标只检查实际读取字段。

计算投影提供 `ModuleDocument.visible`；原始索引未求值时保持缺省。`visibleDocumentProjection` 为玩家生成仅含定位信息的隐藏外壳，真实标题、图片、正文、属性和错误不进入该外壳；隐藏不混用 `valid: false`。内部索引保留完整目标，主持 `read` 和内部公式继续取完整计算结果。名称定位先检查条件，可见时才访问名称。源数据及布局不保存可见性结果，模组库忽略整份显示条件。主持权威读取及提交在求值前获取传递引用的原始快照，已访问集合防止重复和原始引用环，候选根替换自身旧版本；求值中不读磁盘。

玩家文档目录和引用集合在搜索、分类与计数之前过滤隐藏结果，未取得当前投影的引用先不展示。详情、引用、预览和固定装备槽共用 `isDocumentVisible` 判定；隐藏装备只撤下内容，不改真实穿戴状态，也不标为未装备。世界卡和引用资料遵守同一显示条件；位置、参与者和回合等玩法关系由模组字段和规则解释。已有详情在撤销揭露后关闭；有显示条件的文档版本变化时不沿用上一版展示内容。普通正文文字与独立媒体不自动继承关联文档的显示条件。显示条件只约束展示；同步传输原始文档，不提供按玩家分别揭露或传输层权限隔离。

布局加载时规范化详情、角色卡、目录、卡片、引用和悬浮场景，模组库与游戏共用同一份布局。目录、卡片和悬浮摘要允许配置主持字段，模组浏览按配置展示完整资料，游戏仍过滤自身或父级非公开的字段。布局不能授予写权限；结构化字段组件保持各自类型及公开性约束。`FieldTable` 的行标识在原始与计算内容校验时均检查唯一性，防止搜索、折叠或列表复用导致条目状态混淆；合法 `null` 结果跳过行校验，按空值展示配置处理；生成的行标识无效时，表格及实际依赖结果失效，严格计算校验仍拒绝无效行标识。

角色卡、建卡预览和普通详情复用文档计算与字段展示；默认角色卡、普通详情、摘要和嵌套字段统一使用 `hideWhenEmpty` 判断空值；作者 HBS 模板通过条件决定普通插值是否展示，默认关闭；只有显式启用才过滤 `0`、空字符串、`null`、缺省值或空数组。未隐藏的 `null` 保留字段并显示“暂无数据”，结构化组件收到合法 `null` 时使用普通空值展示，不生成表格错误；`false` 不属于空值。错误展示优先于空值隐藏：角色卡、详情、摘要、表格及嵌套字段显示“计算失败”，诊断默认折叠。未被布局列出的失败字段仍提供诊断入口。

`fieldErrors` 随本次文档或角色投影传递，不进入业务 `values`、源文件或存档；成功重算后撤下旧错误。公开错误投影沿父字段和对象列表子字段的可见性过滤，只给玩家通用原因；模组库保留完整诊断。

引用集合的搜索、分类及视图状态不落盘。图片、头像只存原始引用，不在文档或角色模型持久保存派生 URL。媒体真实路径由 `media-path.ts` / `media-protocol.ts` 校验。详情图片和 Markdown 图片共用 `components/ImagePreview.tsx`，多图使用 `ImagePreviewProvider` 归组，业务负责图片引用解析。

新增展示组件应同步扩展共享 `packages/module/src/schema/document-field-view.ts` 的严格 Schema、字段类型及公开性验证、详情与角色卡消费者；带写入能力的交互必须单独定义后端权限，不能从布局推断。状态职责见[游戏状态实现](游戏状态实现.md)。修改共享计算、权限或文件格式后运行平台回归，规则见[测试维护](测试维护.md)。

## 文档渲染与展示投影

普通详情保留 `grid/split` 简单配置，自定义详情与 `sheet` 使用 `template-layout.ts` 的 Handlebars 模板协议。`document-templates.ts` 将默认详情和简单配置转换为内部预设描述，由 `DefaultDocumentLayout` 保留默认字段展示。角色卡与世界卡通过 `DocumentSheet` 选择独立的 `sheet`，不从详情 DOM 复用内容。默认角色卡按详情字段顺序生成，世界卡需要显式配置。

### Web Component 宿主

`DocumentDetail` 与 `DocumentSheet` 只使用 `DocumentRenderer`；`DocumentCardContent` 和 `DocumentPreview` 在配置 `card.content/hover.content` 时也使用同一宿主，否则保留默认摘要。宿主根据渲染器映射创建自定义元素，通过 `input` DOM property 传入布局、当前文档快照和内置运行环境，不把对象序列化为 HTML 属性，也不解析模板或维护内部节点。可选 `onAction` 接收 `tarp-renderer-action` 自定义事件；事件数据为 `type` 与可选 `payload`，嵌套卡片由最近宿主处理。事件只是请求通道，不直接授予写权限；HBS 控件仅提供只读交互。

`document-renderer-element.tsx` 注册真正的 `tarp-hbs-renderer` 自定义元素；它自行创建 ShadowRoot、同步应用样式与主题，持有独立渲染根。更新 `input` 会读取最新投影；移除元素后清理样式和主题观察器、卸载渲染根并释放运行上下文。清理延迟至微任务，避免 DOM 移动或 React StrictMode 重挂载时误销毁。服务端静态输出由渲染器提供声明式 Shadow DOM 内容，不需要浏览器全局对象。

HBS 渲染器内部保留 React 作为宿主组件的实现工具，由 `HandlebarsContent` 解析模板并组合引用、物品格、图片和 Markdown；页面 React 不参与这些节点的拼装。`document-renderer-runtime.tsx` 显式传递引用索引、媒体、房间、查询缓存、嵌套卡片祖先和图片预览环境，避免独立根丢失上下文。该运行环境不属于模板数据或对模组开放的 API。外链事件通过 composedPath 识别 Shadow DOM 内的链接。

目前公开模组格式提供 HBS 渲染入口，尚未开放任意作者 JavaScript 组件的加载协议，也不提供独立浏览器预览。扩展渲染器时应遵守 property 输入与 DOM 事件边界，单独实现加载、生命周期和权限约束。

### 摘要卡片与悬浮内容边界

`card.content` 与 `hover.content` 独立校验、加载模板文件和组件绑定；组件绑定同样接受字段类型校验。列表、卡片外框、打开详情和选角行为保持在平台组件；内部交互使用 composedPath 判定，避免引用、图片预览或折叠操作同时触发外层卡片。

悬浮的触发、宽度、定位、滚动区和关闭由 `DocumentReferences` 的 PreviewCard 容器维护。模板只替换内部内容，实例附加摘要仍由 `DocumentPreview` 追加。`hover.enabled` 对模板同样有效；通过 `PreviewCard.Portal` 默认挂载策略仅在打开时创建预览内容，关闭动画结束后释放自定义元素。文档隐藏时不创建模板，默认摘要与模板使用相同的公开值投影和错误诊断。

### Handlebars 与组件绑定

`layout-templates.ts` 加载模组内模板、CSS 和 partial，核对真实路径并拒绝目录越界、缺失和重复来源。文件内容内联到加载后的布局，冻结副本、同步和恢复使用已加载内容。`handlebars-template.ts` 缓存最多 128 份独立模板配置；CLI 校验语法、静态 HTML 与字段绑定，运行时再次检查动态输出。模板不能执行脚本、事件属性或原型方法，不接受任意第三方自定义标签。

模板数据仅包含当前投影的公开元数据、业务 values、声明的展示字段与错误通道；沿对象和对象列表过滤非公开子字段，失败源值置空。模组库使用完整资料可见范围。模板没有原值、引用加载器和写接口，未引用或条件隐藏的错误保留文档级诊断。

作者模板用 HBS 插值与 HTML/CSS 排列普通字段、属性、资源条、分组和计数。宿主能力通过 `tarp-reference/item-grid/image/markdown` 直接传参；字段路径绑定对象或列表，标量属性按 Schema 转换。引用可使用 `field` 或动态 `value`，支持链接与目标 sheet 展示，沿用循环及深度限制。物品格通过 `InventorySlots` 展示条目与空槽，保留图片、数量、实例摘要和引用交互，不附带标题、计数、工具栏或规则容量判断。简单详情的 `fieldViews` 用于默认展示，不属于作者模板 API。

`display-fields.ts` 在业务求值之后，使用公开字段投影与源字段错误执行展示函数。函数显式输入没有业务原值、引用加载或其他展示结果。客户端在同批 SES Compartment 中编译展示函数，Node 默认使用 `Function` 编译器并最多缓存 256 项；每次求值重新生成函数，输入为独立副本并通过只读代理传播来源错误。结果通过 `displayValues/displayErrors` 传递到详情、角色卡、草稿与预览，不合并到业务 `values`。文档求值缓存和版本检查覆盖展示结果；严格模组校验执行展示函数但不把结果放进源文档。字段求值失败、类型错误只在展示入口显示局部错误。

详情弹窗与角色卡侧栏的宽度、滚动及窄窗口适配见[界面设计](界面设计.md#文档容器与侧栏)。
